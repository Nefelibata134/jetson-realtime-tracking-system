# 安全事件记录 Schema

安全事件以 JSON Lines 格式持久化。每个非空行都是一条完整事件记录，可以独立解析。

## 版本 1.0

```json
{
  "schema_version": "1.0",
  "event_id": "evt-36f29680b4d78226",
  "session_id": "20260817T110500.123Z-a19c73e2",
  "source_id": "csi:0",
  "stream_generation": 0,
  "recorded_at_utc": "2026-08-17T11:05:04.411Z",
  "event_type": "line_crossing",
  "rule_id": "directional-crossing",
  "track_id": 2,
  "class_id": 0,
  "frame_sequence": 131,
  "pts_ns": 4366667000,
  "anchor": {"x": 0.516, "y": 0.992},
  "direction": "positive_to_negative",
  "evidence": {
    "snapshot_path": "outputs/events/snapshots/evt-36f29680b4d78226.jpg",
    "clip_path": "outputs/events/clips/evt-36f29680b4d78226.mp4"
  }
}
```

| 字段 | 含义 |
| --- | --- |
| `schema_version` | 消费端兼容性契约。 |
| `event_id` | 从同一会话内的事件身份字段确定性生成的稳定 ID。 |
| `session_id` | 每次运行调用的唯一 ID。 |
| `source_id` | 输入源，例如 `csi:0` 或 `file:input.mp4`。 |
| `stream_generation` | 输入源成功重启后递增。 |
| `recorded_at_utc` | 创建记录时的 UTC 墙钟时间。 |
| `event_type` | `roi_intrusion`、`line_crossing` 或 `dwell`。 |
| `rule_id` | 稳定的规则配置标识。 |
| `track_id` / `class_id` | ByteTrack 身份与检测类别。 |
| `frame_sequence` | 触发事件的采集帧序号。 |
| `pts_ns` | 输入源显示时间戳，单位为纳秒。 |
| `anchor` | 归一化后的轨迹框底边中心位置。 |
| `direction` | 穿线方向；非穿线事件为 `none`。 |
| `evidence` | 已验证的证据文件路径；缺失文件使用 JSON `null`。 |

## 身份与去重

`event_id` 是以下字段的确定性 FNV-1a 摘要：`session_id`、输入源 ID、
`stream_generation`、事件类型、规则 ID、轨迹 ID、类别 ID 和触发帧。日志以追加模式
打开前会加载已有 ID，因此既能拒绝当前进程内的重复提交，也能在重新打开同一日志后继续
去重。新进程会获得新的 `session_id`，后续调用即使复用了跟踪 ID，也不会与早期事件冲突。

## 证据提交顺序

证据按以下顺序提交：

1. 渲染带标注的触发帧。
2. 写入临时 JPEG 或 MP4。
3. 关闭并验证文件，然后原子重命名。
4. 向 JSONL 日志追加包含已验证路径的事件记录。
5. 刷新日志流。

该顺序可以防止记录声明一个从未创建的证据路径。进程中断可能留下未被引用的文件，但不会
生成一条已经成功追加、路径却是伪造的记录。

## 事件片段

事件片段为可选功能。记录器为配置的事件前时长维护有界原始帧环形缓冲，并在事件后时长
结束时完成片段。只有片段关闭且验证通过后才发布 JSONL。关机或流代次重置时，待完成片段
会提前收尾，从而避免混入两个输入流代次的帧。

原始预缓冲理论上限为：

```text
width * height * 3 bytes * application FPS * pre-event seconds
```

在 1280x720、30 FPS、事件前 2 秒的配置下，上限为 165,888,000 字节，约 158 MiB。
相同设置下的 1920x1080 约为 356 MiB。`event_clip_prebuffer_peak_bytes` 报告实际
观测到的高水位。

片段默认仍使用 MP4V，收集、等待编码和正在编码的任务合计最多 2 个。
达到上限会保留事件记录和截图，但片段路径为 `null`；这表示证据缺失，不是事件未触发。
片段任务在独立线程内编码，停止时等待编码收尾；主线程计时不包含异步编码完成时间。

可显式选择 `--event-clip-encoder mp4v|x264`、`--event-clip-capacity N`（1–8）和
`--event-clip-bitrate-kbps N`（x264 默认 10000）。x264 复用标注录像的既有编码后端，
需要启用 GStreamer 构建；不会因后端不可用静默回退。任务队列与总任务容量使用同一上限，
默认仍为每个事件输出独立文件；不合并事件记录或改变检测、跟踪和事件规则。
选择片段编码器不会改变 `--output-encoder` 的标注录像设置，反之亦然。

运行指标 `outputs.event_clips` 额外记录 `encoder`、`capacity` 和 `bitrate_kbps`；
MP4V 的 bitrate 字段为 0（不适用），禁用片段输出时 encoder 为 `disabled`、capacity 为 0。
`encoding_total_ms` / `encoding_max_ms` 包含打开、写入、关闭与文件最终化，不能相加代替 E2E P95。

片段拥塞诊断字段均在 `outputs.event_clips` 下，终端摘要使用 `event_clip_` 前缀：

| 字段 | 计量边界 |
| --- | --- |
| `events_skipped_capacity` | 收集、排队与正在编码的任务合计达到容量上限时，被拒绝的事件数。 |
| `events_skipped_queue` | 已收集任务提交时编码等待队列已满，未能分配片段的事件数；共享任务按事件数计。 |
| `events_skipped_worker_queue` | 编码线程异常后丢弃的等待队列内事件数，不含正在失败的任务；异常仍向调用方传播，不能据此视为完整对账。 |
| `pending_jobs_high_watermark` | 新物理任务进入收集阶段时，总任务数的高水位，含随后提交队列失败的短暂收集任务；共享事件不增加任务数。 |
| `queue_wait_samples` | 编码线程实际取出的物理任务数，含取出后编码失败的任务。 |
| `queue_wait_total_ms` / `queue_wait_max_ms` | 从提交等待队列到编码线程取出的单调时钟耗时总和/最大值，不含事件前后帧收集时间和编码时间。 |

三个拒绝/丢弃计数之和对应既有 `skipped`，不覆盖异常中所有未完成事件；失败时仍需逐条
核验 JSONL、截图及片段。排队耗时与编码耗时分别记录，不能由总和或最大值推算 P95、
告警发布延迟或完整流水线 E2E。指标增加不改变容量、队列策略、编码器和既有有效计分门槛。

增大容量会提高内存上限，不能解决持续过载，也不保证零缺失。除预缓冲外，保守原始帧上界为
`capacity * (round(pre_seconds * FPS) + 1 + round(post_seconds * FPS)) * width * height * 3`。
720p/30、前2秒/后3秒、容量8对应约3.11 GiB，加预缓冲约3.27 GiB；重叠片段共享帧会降低实际值，
但预算不能预设这种节省。这里不包含模型、解码器、编码器、标注录像队列和其它系统内存。
容量8仅作为显式开发候选，需重新验证带真实事件负载的FPS、E2E、丢帧、内存与媒体完整性；
默认配置、已有失败结果和持续运行结论不因此改变。

### 显式的重叠片段共享

`--event-clip-share-overlap` 默认关闭。启用时，同一会话、输入源和流代次内，尚在收集的
片段可以接纳后续事件并延长结束时间。每条事件保留独立 ID、截图和 JSONL；仅 `clip_path`
可以相同，不按录像文件数计算事件数。已经提交编码的任务不会重新打开或追加。

`--event-clip-max-shared-seconds` 默认 10 秒（最大 60 秒），
`--event-clip-max-shared-events` 默认 32 条（最大 256 条）。超过任一上限时创建新任务；
总任务容量仍有界，满载时保留事件与截图并以空片段路径报告缺失。共享不保证零缺失。
最大帧数为 `round(max_shared_seconds * FPS) + 1`，必须容纳事件前后窗口。
流代次、帧序、PTS 或画面尺寸不连续时提前收尾并清空预缓冲，不跨断点共享。

指标 `started/completed` 统计物理录像任务，`events_completed` 统计成功完成编码并分配路径的
事件，`events_shared` 统计加入已有收集任务的事件（加入不等于最终成功）。`skipped` 仍统计
缺失录像的事件数。重复 ID/已有文件复用单独计入 `reused`，不算本轮新编码成功。
新目录、无复用且无失败时，已留证事件数应等于日志事件数；独立路径数应等于完成录像数。
完整性核验还需逐事件确认录像覆盖前后窗口，不能仅检查路径非空。启动、结束或断流造成的
窗口截断应单独标记。共享会延迟首条事件 JSONL 的发布，最长等到共享窗口收尾加排队/编码；
它不改变事件的输入 PTS，也不代表同步告警延迟得到改善。

共享模式保守原始帧预算将上述每任务帧数替换为 `round(max_shared_seconds * FPS) + 1`。
720p/30、10 秒、容量 8，加前 2 秒预缓冲约 6.36 GiB，尚不含模型与其它内存；
选择上限必须同时考虑设备内存，不能因平均资源较低忽略最坏负载。

## 可选 ROI 离区确认

`--event-roi-exit-margin`（归一化距离，0–0.25）与 `--event-roi-exit-seconds`（输入 PTS 秒数，
0–60）默认均为 0，保留原判定。显式启用后，已进入 ROI 的同一轨迹必须在区域外、距多边形
边界至少指定距离，并持续被观测满离区时长，才重新允许触发进入事件。短暂漏观测不算连续
离区；流重置或轨迹过期清理旧状态。初次进入、新轨迹、穿线和停留规则不受此选项修改。
该迟滞可抑制边界抖动，但也会抑制真实的短时/浅距离离区再进入，需作为显式候选验证取舍，
不能把事件数降低直接当作误报改善。

## 可选穿线持续确认

`--event-line-confirm-seconds` 必须配合 `--event-line`，范围为 0–60 秒（非零值至少 1ns），默认 0 保留
既有穿线行为。正值通过输入 PTS 计时：同一轨迹须在警戒线同一侧、现有中性带外连续被观测
满指定时长，才建立初始稳定侧；此后另一侧也必须满足时长及 `confirmation_frames`，
才确认方向变化。回到原侧或中性带会取消待确认计时；中性带距离和方向限制均不修改。

交点判定使用原稳定侧观测与首次另一侧观测构成的线段，须与有限警戒线相交；不会用较晚的
确认位置替换这次几何判定。事件的 `frame_sequence`、`pts_ns`、`anchor` 和截图均来自
确认帧，不回填为首次越线时刻，因此存在配置时长及离散帧带来的确认延迟。

轨迹漏观测、帧序不连续、PTS 不递增时重新建立稳定侧，不把不可见的路径当作已观测跨线。
新身份独立计时，流代次变化清空状态。正常跨线和返回仍可分别触发，但真实的快速跨线后
立即返回可能被抑制，遮挡期间跨线也可能漏报。该选项是需要开发验证的行为取舍，不能以
事件总数下降证明准确率改善，也不能追溯改变使用旧规则的结果；ROI、停留和 ByteTrack 不变。

## 可选 ROI 入区持续确认

`--event-roi-entry-seconds` 需要配合 `--event-roi`，范围为 0–60 秒（非零值至少 1ns），
默认 0 保留既有行为。正值要求同一轨迹的框底边中心在 ROI 内连续被观测满指定输入 PTS
时长，并满足既有 `confirmation_frames`，才触发入区事件。漏观测、帧序缺口或 PTS
不递增会重新开始待确认计时；新轨迹、流重置及轨迹过期不继承旧计时。

事件帧序、PTS、锚点和截图来自确认帧，不回填首次入区时刻。该选项可以与 ROI 离区确认
共同使用，但两者分别控制进入与重新允许入区，均不改变 ByteTrack、穿线或停留计时。
例如 0.5 秒会抑制短暂入区观测，也会延迟有效报警或漏掉真实的快速通过；连续漏观测
可进一步增加确认延迟。持续存在的背景误检仍可能报警，不等于增加了人物/椅子分类能力。

## 可选停留重新触发保护

`--event-dwell-rearm-on-exit` 需要已有 `--event-dwell-seconds`，默认关闭。
启用后，同一轨迹已触发停留时，漏观测不会单独清除“已报警”状态；需要连续观测到离区，
满足停留规则的 `confirmation_frames` 后才重新允许下一次停留。缺口或重复 PTS 两侧的
离区观测不能拼成连续离区。首次停留尚未触发时，仍沿用 `max_gap_frames` 的缺口重置规则，
不是把长时间不可见算作停留。该保护不使用 ROI 规则的离区边距或离区秒数。

状态仍受既有 `stale_after_frames`、流代次/时间线重置及显式 `reset()` 清理；不是无限期
保留，也不合并不同轨迹 ID。代价是未观测到的真实离区再进入可能被抑制；跨 ID 的重复
停留与重复入区不会因此消失，不能仅按事件减少评价质量。

上述两项为显式开发选项，未加入默认服务环境文件或启动器；需通过独立指定完整参数的
检测程序命令启用。合成状态测试仅证明机理，不能替代实际场景事件真值、完整链路性能与
恢复验证；既有协议与历史事件记录不追溯修改。

才形成完整矩阵。设备验证已生成PNG的字节，不换OpenCV版本重缩放。程序本身不停止服务

trace保留全部检测、人物轨迹ID/框/锚点、三类事件、实际阶段耗时及事件附近候选轨迹到

## 四组不变量

机器可读配方见 [v5 配置](../../configs/benchmarks/tiny_source_resolution_v5.json)。配方中的
`PREPARATION_NOT_FROZEN`为通用模板状态，保留原哈希；具体执行以单独冻结的选择清单为准。

| 组 | 原始输入 | engine 输入 |
| --- | --- | --- |
| `native_tiny416` | 1280×720 | 416×416 |
| `native_tiny640` | 同一 1280×720 | 640×640 |
| `low_tiny416` | 同源 384×216 | 416×416 |
| `low_tiny640` | 同一 384×216 | 640×640 |

四组均为 `score=0.10 / nms=0.45 / track=0.30 / new_track=0.40 / match=0.80`，
`buffer=30 / second_match=0.50 / unconfirmed_match=0.70 / frame_rate=30`。只使用原有
Tiny416、未调参 Tiny640 engine 及其固定 SHA-256，不重建，不加入 v3 调参方案。

质量回放拟保持 25W 与原 DVFS 控制。逐帧顺序读取，无计分预热、跳帧或丢帧，不强制用
墙钟 30 FPS 推进以致模型较慢时丢帧。两种源尺寸共享帧序号及原 PTS；每段重置跟踪/事件
状态。复用 Detector、ByteTrack 与事件实现，不复刻另一套规则。

此顺序回放不是持续服务的有界队列负载模型：只能报告回放吞吐和实际测得阶段耗时。
未采集的 E2E、采集队列延迟、事件 I/O 或遥测记为 `N/A`，不能由阶段 P95 相加得到 E2E。

## 配对资产与验证

网络原片先完整解码成不带标注的 BGR8 PNG，保留原视频 SHA-256、解码器版本/完整命令、
逐帧 PTS、原序号与选取区间。预先按动作覆盖选择连续片段，不循环、不补帧、不时间插值。
30 FPS 以外素材暂不由工具强行改帧率；若值得采用，须在任何预测前修订草案并核对时间语义。

`prepare_source_resolution.py` 接受带来源证据的 `native.json`，逐帧验证输入哈希，再使用
OpenCV `INTER_AREA` 从同一份 BGR8 像素降采样，PNG compression=1。原图逐字节复制，不
再有损编码；低清图回读须逐像素等于缩放结果。记录 OpenCV/NumPy/Python 版本及原生/低清
文件 SHA-256、像素 SHA-256、序号和 PTS。验证时缩放库版本不同则停止，不静默换容差。

严格验证 `0..N-1` 完整序列、唯一文件引用、单调 PTS、30 FPS 网格误差≤1ms。该容差仅处理
时间基量化/采集时间抖动，不允许少一帧；缺帧的约 33.33ms 偏差不会通过。两份素材每个 PTS
必须完全相等。采集的意外丢帧、解码失败或序列缺口任一非零即拒绝。

目录及 manifest 均拒绝覆盖，失败时保留部分输出供诊断；不会将部分输出标为有效素材。
哈希和来源声明不能自动证明画面原生或使用权，素材持有人审核仍是必需步骤。

## 预测前冻结与计分草案

先观看无标注原片，锁定至多三段完整区间、ROI 矩形、有限警戒线和共用的 dwell 区域。
几何使用归一化坐标；基准点为框底边中心。每段均审核完整事件，整个素材集覆盖三类阳性
及有人活动但不应报警的区间。远近人物和遮挡若不足，明确标为覆盖限制，不能伪造满足。

真值独立于模型预测：每条记录保留 `event_id / subject_id / rule_id / event_type /
frame_sequence / anchor`，穿线另含方向。关键事件前后 2 秒至少有两个可审查的人工原图
锚点观测，身份不明确或脚部完全遮挡处记录不确定性；审核时解决真值歧义后再冻结。
未见预测、授权、原生来源、全片标注及负例检查通过，方可生成 `frozen.json`。

事件语义沿用实现：ROI 连续确认 2 帧；穿线确认 1 帧、side epsilon=0.01、任意方向；
dwell=3 秒、确认 2 帧、最大缺口 3 帧；stale=300 帧。dwell 计时使用 PTS 而非处理速度。
三类均计分，不把可见的其他类型结果静默排除。

计分复用现有 `evaluate_caviar_events.match_events` 的确定性一对一匹配，先按片段、事件
类型、rule ID 分区。匹配方向必须相同，归一化锚点距离≤0.2；时间容差拟保持既有 2 秒
口径，即 30 FPS 下 60 帧（CAVIAR 为 25 FPS 下 50 帧），这不是看到结果后的放宽。
需在真实素材冻结时确认该草案。逐类/逐视频/聚合保留 TP、FP、FN，微聚合先相加计数再算
Precision/Recall/F1；零分母显示 `N/A`，不能展示为 100%。

逐帧 trace 至少记录：源序号与 PTS、检测框/分数/类别、跟踪 ID/框/状态、底边锚点、事件
记录。计分前验证 trace 与素材逐帧完全对应、无无效帧/丢帧/代次重启；失败标为
`NOT_SCORED`，保留日志，停止且不自动重跑。现有 MOT calibration 专用诊断入口不放宽
到任意素材。**新trace与计分连接及目标编译已完成检查；特权预检、真实推理和质量仍未验证。**

## 差异解释与证据完整性

完整报告必须包含四组逐视频、逐类和聚合事件矩阵，以及检测总数、含轨迹帧数、轨迹观测、
各触发窗口内 ID 变化、底边锚点到线的有符号距离和到 ROI 边缘的距离。
复核每个 FN 与新增 FP，不只分析改善样例：

- 穿线：是否两侧均有观测、身份是否改变、锚点是否跨过有限线段；身份分裂不能只解释为漏检。
- 停留：同一身份的在区 PTS 是否达到 3 秒、缺口是否超过规则、是否被锚点抖动重置。
- ROI：同一真实人物的重复 ID/重入与真正新人物分开，保留全部重复报警。
- 保留成功/失败事件的同源逐帧对照，不根据预测改真值、ROI 或取片区间。

先比较每个源分辨率内 `Tiny640−Tiny416` 的质量差，再比较两种源分辨率下的差值。
只有收益在原生输入上更清楚且关键事件证据相符，才支持“源细节限制收益”的解释；不能
仅凭总体 F1 宣称因果，更不能把本轮结果追溯为旧 CAVIAR 的通过结论。

事件是否预测正确与证据是否保存分别计数：截图/片段/标注视频缺失、空文件、片段截断、
编码队列丢弃均单列。片段缺失不增加事件 FN，正确 JSONL 也不代表证据留存通过。

推理前另行列出实际资产路径/哈希、源码及二进制快照、预计停服时间与恢复预留，获得授权。
只有包装器中断/超时恢复自测通过后才能停服；超时不自动延长。正常、异常或中断后恢复
原功率、原时钟及 Tiny416，核验实际 engine、active/running、NRestarts=0 与新真实帧递增。

若网络原片仍不足，才安排 CSI 备选：60 FPS 采集、30 FPS 交付，预热 150 交付帧与正式
丢帧分开；拟录三段各 40 秒，包含双向穿线、入区停留至少 5 秒再离开、负例走动及适量
遮挡。备选窗口≤10分钟、预留≥1分钟恢复；仍需单独确认，不自动录制或停服。

本轮不运行 holdout、不扩参数网格、不自动提交或推送。模型、录像、截图、逐帧真值与原始
运行日志仅存于忽略目录。若质量值得继续，另行验证真实 CSI 720p/约30 FPS 与真实事件
负载；MAXN_SUPER+锁频可作为候选条件但须单独确认窗口，1080p 不是主目标。

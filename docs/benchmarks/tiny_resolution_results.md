# Tiny416 / Tiny640 同权重 calibration 对照结果

## 召回改善，但未通过扩大验证的连续性门槛

2026-09-05 在目标 Jetson 的 25W、未锁频 DVFS 条件下，完成同一原始权重的
Tiny416 / Tiny640 首轮同阈值 MOT17 calibration 对照。两个模型均完整处理四段共 3,141 帧，
执行与证据核验 PASS；**扩大验证的质量门槛 FAIL**，默认仍为 YOLOX-Tiny416。

Tiny640 的整体 HOTA、IDF1、MOTA 与跟踪输出 Recall 均提高，原图高度 `h<100 px` 的检测
Recall 从 11.466% 提高到 28.242%。但该组跟踪中断由 75 次增至 194 次，没有满足事前规定
的“中断严格减少”。本轮因此停止扩大验证，未调参，未执行 CAVIAR development、CSI、
RTSP、压力测试或任何 holdout；不能称为模型升级验收完成。

这里的“中断”指有效 GT 连续存在时的匹配→漏配→重新匹配事件，按首次漏配框高度分组。
它是自定义诊断，定义和门槛已在预测前冻结，详见[对照协议](tiny_resolution_protocol.md)。
匹配覆盖增加也会增加中断暴露机会，绝对次数上升不能单独证明所有轨迹的稳定性都下降；
这一限制不构成事后放宽已冻结门槛的理由。

## 小目标检出增加，稳定匹配覆盖仍有限

分组使用原始 GT 在原图中的人物框高度，不按网络输入尺寸重算。`h<100` 合计 15,891 个
有效观测，不是 15,891 个独立人物。先按官方预处理和全帧匹配确定 TP/FN，再按高度归组；
不在各组内独立匹配。以下全部为自定义分组诊断，不是官方分组 TrackEval 指标。

| h<100 指标 | Tiny416 | Tiny640 | 固定门槛 |
| --- | ---: | ---: | --- |
| 检测 TP | 1822 | 4488 | 随 Recall 核验 |
| 检测 FN | 14069 | 11403 | 严格减少：PASS |
| 检测 Recall | 11.466% | 28.242% | 严格提高：PASS |
| 跟踪 TP | 1005 | 2482 | 描述性诊断 |

整体 HOTA/IDF1/MOTA 不回退三项均 PASS，但中断条件失败，因此组合门槛 FAIL。检测收益
不能直接等同于足以支撑穿线或停留事件的稳定轨迹；本轮没有事件 F1 证据。

### h<50 仍然困难，中断增量集中在 02 和 10

Tiny640 的 `h<50` 检测 Recall 只有 7.370%，匹配跟踪 Recall 为 3.219%；50–<100 px
组的检出改善更明显。高度更大的组同样贡献了大量 TP 增量。

| 原图 GT 高度 | 有效 GT 观测 | 检测 Recall % 416/640 | 跟踪 Recall % 416/640 | 跟踪中断 416/640 |
| --- | ---: | ---: | ---: | ---: |
| h<50 | 2361 | 6.057 / 7.370 | 1.864 / 3.219 | 4 / 18 |

| h≥200 | 20462 | 76.312 / 77.627 | 73.712 / 75.770 | 155 / 152 |

小目标中断增加 119 次，其中 02 增加 28 次、10 增加 77 次；两段合计占增量的 105 次。
05 为 54→68，04 为 0→0。更高检测覆盖提供了更多可能出现中断的匹配片段，因此还不能
只凭次数区分“新增目标暴露”与“原有目标轨迹变差”。02/10 的 AssA 同时下降，是关联质量
需要继续诊断的另一条证据，但不证明某个 ByteTrack 参数就是唯一原因。

[高度诊断表](tiny_resolution_height_diagnostics.csv)。04 的 `h<50` 分母为零，Recall 留空
表示不可用；检测框使用临时身份，检测行的中断字段同样留空，不记为 0。

## MOT 吞吐下降，尚无 720p 完整实时结论

以下 FPS 是顺序 JPEG 回放的有效吞吐，包含读取、MOT 写入和两组同时启用的逐帧检测明细
写入。02/04/10 原图为 1920×1080、原帧率 30；05 为 640×480、原帧率 14。所有帧计入统计，
warmup 为 0。它不是 CSI 1280×720 输入的完整链路 FPS。

| 05 | Tiny416 | 837 | 52.396 | 10.483 | 2.762 | 0.689 | 0.444 |
| 05 | Tiny640 | 837 | 34.699 | 19.454 | 2.035 | 1.663 | 0.528 |
| 10 | Tiny416 | 654 | 33.561 | 10.406 | 2.469 | 0.464 | 0.356 |
| 10 | Tiny640 | 654 | 23.471 | 19.226 | 3.556 | 1.602 | 0.643 |

Tiny640 的 TRT P95 为 19.130–19.454 ms，额外计算成本真实存在。不能由 MOT 低于 30 FPS
直接判定 CSI 必然失败，也不能用 05 的 34.699 FPS 证明 720p/30 达标或存在充足余量。

逐帧 JSONL 验证两者各自的 1…N 编号完整、无重复、无缺口，未处理帧为 0。MOT 入口不使用
采集队列，所以采集 dropped frames 不适用。E2E P95、事件 I/O、穿线/停留/入口入侵的
TP/FP/FN 和 Precision/Recall/F1 均未测量，不由阶段 P95 推算；机器可读表留空表示不可用。
各阶段 P95 只保留逐序列值，不相加，也不平均为整体 P95。

## 资源采样反映额外负载，不代表长期热稳定性

tegrastats 以 1 秒间隔覆盖各模型批次，Tiny416 为 90 个样本、Tiny640 为 127 个样本。
采样包含 engine 加载、文件 I/O、序列间开销和其他系统进程，不是模型独占资源；下表的
内存是系统 RAM，不是该模型的 GPU 显存。每项为均值 / 最大值。

| 资源 | Tiny416 | Tiny640 |
| --- | ---: | ---: |
| 有效 CPU 核利用率均值 % | 14.198 / 16.833 | 13.827 / 16.500 |
| GPU 利用率 % | 34.144 / 56.000 | 45.953 / 99.000 |
| 系统 RAM MB | 3053.089 / 3061 | 2989.551 / 2994 |
| 输入功率 W | 5.856 / 6.064 | 6.271 / 6.664 |
| CPU 温度 °C | 55.451 / 56.625 | 54.729 / 55.031 |
| GPU 温度 °C | 55.814 / 56.843 | 55.184 / 55.593 |
| 结温 °C | 56.664 / 57.656 | 56.016 / 56.218 |

Tiny640 的功率与 GPU 利用率均值更高；其 RAM 和温度采样略低不能证明内存更省或长期
热行为更好。固定先416后640、未随机交叉重复，缓存、风扇与热惯性仍可能影响短测结果。
本轮只约束相同功率和时钟控制，不把 DVFS 下的瞬时频率视为固定常量。

## 核验边界与后续决策

104 份板端文件与本地副本逐一 SHA-256 一致。主机以相同 NumPy 1.21.5、SciPy 1.8.0 和
固定 TrackEval 重新取得16组模型/序列/检测或跟踪匹配，并用按 GT 连续片段划分的另一种算法
复算中断，结果与板端一致；全部分组 TP 与官方 CLEAR TP 对账。复算只读取已有 calibration
预测，没有重新推理、调参或读取 holdout。原始模型、图像、GT、逐帧预测和运行日志不进入 Git；
公开表格只保存汇总工程指标及可追溯哈希。

主机复核在 WSL Ubuntu-22.04 完成：Release/GStreamer 构建、16项 CTest、x264专项、72项
Python、MOT应用C++17语法、Shell语法、包含未暂存公开增补的发布检查及 diff check 通过。
x264专项有意制造背压，12提交/3写入/9丢弃是该确定性测试的预期计数，不是本轮视频性能。
Windows 原生72项 Python 中有1项 WinError1314符号链接权限失败、8项POSIX跳过；不称
全平台测试全部通过。Windows缺少符号链接权限不改变已在Linux实际执行的相应测试结果。

这些是单次固定校准结果，不提供独立泛化结论或跨运行置信区间。官方416图与本次重导出图的
导出器版本不同，参数和固定图像等价证据并不保证全部输入位级一致。阶段延迟只保存现有
入口计算的 P95，没有逐帧阶段时长数组，因此不能独立重算分位数或生成新的延迟分布。

按原门槛停止扩大验证，保留 Tiny640 候选资产与本轮收益/失败证据，Tiny416 继续默认。
尚待解决的问题是新增小目标覆盖中哪些轨迹被稳定保留、哪些产生短暂匹配或身份切换；若
重新启动，应先提出并确认有界诊断/调参方案，保留本轮同阈值结果，不事后改写门槛或旧结果。
只有在质量门槛通过后，才讨论固定 CAVIAR development 事件质量与最终640尺寸的 CSI720p30
完整链路验证。MAXN_SUPER、锁频和新的独立 holdout 仍需独立批准。

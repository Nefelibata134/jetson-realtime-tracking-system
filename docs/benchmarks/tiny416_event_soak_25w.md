# Tiny416：25W 动态调频60分钟事件链路实测

2026-09-09，Tiny416事件规则候选r9在CSI 720p输入下完成108600帧、约60分20秒测量。
**有效FPS为30.0000447，正式丢帧和序列缺口均为0，保护进程正常退出并恢复原r8服务。**
原冻结协议因内存增长门槛保持`NOT_ACCEPTED`；不能将本次记录概括为全部稳定性指标通过。

TRT含同步/输出复制。逐帧诊断写出成本计入本轮I/O，不能声称这是完全无诊断开销的部署性能。

但有限计数器和动态频率变化不能证明所有降频机制均未发生。与旧短测动作、输出及诊断负载
不同，不将本轮延迟/功率降低单独归因于规则优化。

## 事件与媒体完整性

共11条事件：ROI入区7、穿线4、停留0。六个10分钟诊断块的事件数为`0/6/0/0/1/4`。
本轮是自然活动负载，未要求每个窗口产生事件；缺少停留输出只能说明覆盖不足，
没有完整GT不能推断停留FN或事件Precision/Recall/F1，也不能由报警数少判断准确率提高。

11条事件均有截图与有效片段路径，7个物理片段覆盖全部事件，4条事件共享片段。
片段共编码1088帧；容量、队列及后台工作队列拒绝均为0，任务高水位2/8。
板端对11截图和7片段完成软件解码、尺寸、前后哈希与共享窗口帧数核验，媒体检查PASS。
后台编码总计18649.129ms、单任务最大2881.087ms，停止flush为23.337ms，均不冒充同步事件I/O。
全程录像关闭，其写出0/0帧是未启用，不是全程录像通过。媒体完整不等于内容或报警语义正确。

## 原内存门槛失败

排除资源采样开始后的首5分钟，以后续第一个RSS样本为基点，计算峰值增长及时间回归斜率：

| 内存诊断 | 实测 | 原门槛 |
| --- | ---: | ---: |
| 基点 / 峰值 / 最后样本 | 504.78 / 1012.47 / 549.50 MiB | — |
| 峰值相对基点增长 | 507.69 MiB | ≤256 MiB，FAIL |
| 线性回归斜率 | 0.595 MiB/分钟 | ≤2 MiB/分钟，PASS |

两项必须同时满足，因此原`memory_stability=false`及整体`NOT_ACCEPTED`保持不变。
507.69 MiB是峰值增长，不是结束净增长；最后样本已经回落，不能直接称为同等大小的内存泄漏。
是否涉及片段缓冲、编码或诊断分配仍需定位，本报告不以推测覆盖原失败，也不宣称内存问题已修复。

## 退出、恢复与证据边界

推理子进程exit=0，启动器`python_exit_code=1`、`tee_exit_code=0`，对应原内存FAIL而非推理崩溃。
保护进程最终exit=0，中途只读快照显示候选和保护进程存在；本轮没有故障注入，
“保护正常”限于本次运行监管、预算内退出与恢复，不等于已测试全部故障恢复分支。

停服3707.55秒，在90分钟窗口内；恢复原r8服务`active/running`、`NRestarts=0`，
真实帧37→41，媒体检查后636→756。engine、原二进制、启动器、环境、systemd及25W/DVFS控制
前后核验一致。恢复的是原r8，r9默认切换不在本次执行范围内；这些是该轮快照而非永久健康证明。

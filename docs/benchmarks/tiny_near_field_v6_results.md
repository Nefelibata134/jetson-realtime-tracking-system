# Tiny416 / Tiny640 近景事件开发结果 v6

## 结论：两者检出同样的 13 项事件，Tiny640 未带来整体收益

2026 年 9 月 7 日，固定三段 MEVA 门口视频的六次 Jetson 回放完成，
输入、帧完整性、计分和服务恢复证据核验通过。Tiny416 聚合 F1 为 74.29%，
Tiny640 为 72.22%；两者均为 13 TP / 1 FN，Tiny640 多出一次穿线 FP。
状态为 `DEVELOPMENT_NOT_GATED`，不是产品验收 PASS，也不是新的独立外部验证。

三种事件都有正确检出：停留参考 3/3 检出；穿线仍漏 1/6；入区 5/5 检出但两者均有 8 次误报。
当前更需要检查框底边稳定性、遮挡后的状态衔接和重复入区，而非仅增加检测数量。
本结果不修改默认 Tiny416，不覆盖 MOT17、CAVIAR、同源分辨率 v5 或早前 Tiny640 的 FAIL。

## 固定输入、参考与计分口径

本轮按[近景协议 v6](tiny_near_field_v6.md)和
[机器配方](../../configs/benchmarks/tiny_near_field_v6.json)执行，没有追加搜索或修改真值。

- 三段来自同一门口机位、同一源视频：`meva_door_wait_exit`（出门）、
  `meva_door_wait_enter`（进门）、`meva_door_interaction`（交互）。下文使用括号内简称。
- 源 1920×1072 上下各补 4 像素，再等比缩至 1280×720 PNG，**不是原生 720p**。
  三段为 900 / 900 / 750 帧，共 2,550 帧、85 秒；两模型共处理 5,100 帧。
- 源包没有 PTS，采用冻结的解码序号 / 30 派生时间；原始采集完整性未知。
- 预测前冻结 5 名人物、14 项事件：5 入区、6 穿线、3 停留，包含背景及短时通过负例。
  参考是视觉事件级标注，不是逐帧精密人体框或独立双人标注。
- 五阈值依次为 score / NMS / track / new-track / match：
  `0.10 / 0.45 / 0.30 / 0.40 / 0.80`；ByteTrack 帧率 30、buffer 30、
  second-match 0.50、unconfirmed-match 0.70。
- ROI `[0.37,0.70,0.70,0.995]`，有限警戒线 `[0.50,0.70,0.50,0.995]`，
  停留 3 秒；锚点仍为人物框底边中心。确认帧与稳定侧容差保持协议值。
- 两模型均使用 25W、原 DVFS，不锁频、不重建 engine。计分预热丢弃为 0 帧。
- 匹配按视频、类型、规则划分，方向一致，一对一贪心匹配；时间容差 60 帧、
  归一化锚点距离 0.2。Precision=`TP/(TP+FP)`，Recall=`TP/(TP+FN)`，
  F1=`2TP/(2TP+FP+FN)`；聚合先加计数，不平均逐视频 F1。

每次回放均达到目标帧数，派生序号与时间轴正确，意外丢帧为 0、序列缺口为 0，
`target_reached=true`。这里的完整性不代表原始摄像头未丢帧，也不代表目标轨迹无中断。

## 轨迹与锚点诊断：保住编号不等于保住事件几何

以下帧号均为片段内零起始序号，坐标为归一化底边中心；诊断来自原始 trace 与
[事件状态实现](../../src/event_analytics.cpp)，不是新增的人物身份真值或官方 IDSW 指标。

- **重复入区不全是换 ID。** 两者各 8 次 ROI FP 中，Tiny416 有 4 次、Tiny640 有 5 次
  在同一 ID 先前已报过入区。交互片段 Tiny416 的 ID 2 在帧 378、393 重报；
  Tiny640 的 ID 2 在帧 377、382 重报。其间锚点曾越过 ROI 下沿 `y=0.995`。
  当前实现按每个 ID 的出区/入区状态转换触发，底边出画或抖动可重新启动入区事件。
  其余 FP 还涉及首次过早入区和新轨迹初始化，不能一概称为同一原因。
- **两者漏掉同一项交互穿线。** 参考主帧 398、视觉时间带 393–400，
  方向为 `negative_to_positive`。Tiny416 的 ID 1 在帧 388 后无观测，
  帧 393 出现 ID 3，锚点已为 `(0.4849,0.8718)`；新 ID 没有此前另一稳定侧状态。
  结合遮挡段位置，这是状态衔接失败的证据，但没有据空间近邻直接计算物理人物 IDSW。
- **Tiny640 保留 ID 1，仍发生底边失真。** 同一 ID 在帧 389 的锚点为
  `(0.5116,0.6060)`，帧 393 为 `(0.4797,0.8532)`。按冻结稳定侧容差，
  这两个稳定点的连线与 `x=0.5` 的交点约为 `y=0.696`，落在线段上端 `0.70` 之外。
  因此现有有限线段规则不报事件；该观测支持遮挡导致框底边偏移的解释，
  不能简单归因为“640 也没检测到人”，也不应事后延长线段补分。
- **Tiny640 额外穿线 FP** 在交互帧 389、ID 2，锚点 `(0.5137,0.9842)`，
  方向 `positive_to_negative`，与漏报参考方向相反。它不能补偿前述 FN；
  画面下端的框底边估计与有限线段边界共同影响该类误报。

检测数、跟踪帧和轨迹观测均增加，说明 Tiny640 改变了感知输出；
但没有形成额外事件 TP。跟踪帧指至少有一个轨迹观测的帧，轨迹观测是所有帧轨迹数之和，
不是人物数量、GT 覆盖率或身份连续性评分。

## 复算与边界敏感性

回传 87 个文件保留原字节。核验六份任务/程序/engine 身份、trace/summary 哈希，
重新按冻结输入与原计分实现计算，全部主结果与 `scores.json` 一致；
另用独立的一对一匹配计数实现确认 TP/FP/FN 和聚合公式。
`completion.json` 的 `NOT_SCORED` 是执行完成时的历史字段，随后 CPU 计分退出码为 0，
不能据这个旧字段把已产生的 `scores.json` 误判为尚未计分。

发现原计分输出的视觉时刻敏感性分支读取 `annotation_uncertainty_frames`，
而 v6 标注字段是 `visual_boundary_frames`，导致原“最早/最晚”结果实际未移动参考时刻。
**该问题不影响主分数，但原敏感性输出不能作为有效核验依据。** 原报告与运行源码快照保留；
独立诊断按真正冻结的最早/最晚时刻重算，保持其余锚点、方向、匹配条件不变，
六次结果均与各自主分数一致。因此本轮排名不受这项时间边界复算影响，
但这并不消除几何估读的不确定性。当前共享计分工具已兼容两种时间带字段，
拒绝冲突或无效区间，并补充了实际移动时刻且不改变主结果的回归测试；修复没有重新执行模型。

进门片段等待女子的下端穿线参考为帧 395，Tiny416 / Tiny640 分别在帧 392 / 393 匹配，
锚点距离分别约 0.02797 / 0.02598；参考视觉时间带为 390–397，按其最早/最晚时刻复算也未改变匹配。
该敏感样本保留主结果，没有看过预测后删去；本轮没有改动有限线段几何来测试不同边界。

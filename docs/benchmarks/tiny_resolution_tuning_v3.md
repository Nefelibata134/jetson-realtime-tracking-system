# Tiny640 有界参数搜索与性能矩阵协议 v3

## 目标与结果边界

在同一 Tiny640 FP16 engine 与既有 ByteTrack 实现下，寻找有限搜索空间内质量更好的候选
配置，再用固定开发视频及相同最终配置验证完整流水线。搜索不是全局最优证明，不预设一定
存在同时满足全部要求的配置。默认仍为 Tiny416，服务、默认命令和历史结果不变。

[25W同阈值校准](tiny_resolution_results.md)的小目标中断75→194及原门槛FAIL、
[v2](tiny_resolution_development_v2.md)的原CSI成对验证限制全部保留。本协议另行允许有界
参数开发，不追认旧轮次通过。受限场景下三类事件已触发和短时30FPS的
[CSI证据](tiny_resolution_csi_event_retest.md)可用于功能与当前负载性能说明，不替代带真值
的事件质量对照。所有搜索只允许 calibration/development，不读取或运行 holdout。

机器可读计划见
[`tiny_resolution_tuning_v3.json`](../../configs/benchmarks/tiny_resolution_tuning_v3.json)。
实施状态、执行命令、程序和输入哈希、结果与失败原因另存新目录；协议本身不是执行结果。

## 跟踪参数搜索

复用已保存的 Tiny640 calibration 检测JSONL。这些是score=0.10、NMS=0.45后的人物检测框，
包含每帧原始float值的9位有效数字；不能据此恢复低于0.10的候选框或重做其他NMS。

正式搜索前必须以原五阈值重放Tiny416和Tiny640各四段，调用仓库原ByteTracker与原MOT输出
实现，逐序列重建进程及跟踪状态。原文件SHA校验和完整帧序通过后，重放MOT文件必须与原
板端结果字节一致。任一不一致则停止此主机重放路线，不把非等价重放当作板端基线；先定位
数值、架构或实现差异，再另行确定同平台执行方案。重放时间不作为Jetson FPS或延迟证据。

固定MOT17-02/04/05/10-FRCNN，共3141帧；05使用14FPS，其余30FPS。GT、有效目标、忽略区域、
TrackEval提交与匹配方法沿用原校准协议。每个配置都显式保存score/NMS/track/new-track/match
及buffer，第二关联和未确认轨迹关联阈值保持现值。首轮不改变检测输出。

| 参数 | 有限搜索值 |
| --- | --- |
| score | 0.10，固定 |
| NMS | 0.45，固定 |
| track | 0.25 / 0.30 / 0.35 |
| new-track | 0.35 / 0.40 / 0.45 |
| match | 0.70 / 0.75 / 0.80 |
| buffer | 30，固定 |

共27个组合，包含原0.30/0.40/0.80对照，不在看到结果后追加网格。检测score下探、NMS更改、
buffer扩大或第二关联更改需要新的有界计划与真实检测数据，不能伪称本轮已搜索。

## 选择标准与失败记录

先完整报告每个配置整体及逐序列HOTA、DetA、AssA、IDF1、MOTA、Recall、Precision、TP/FP/FN、
IDSW、Frag；按既有有效GT和原图高度口径报告小目标匹配覆盖与绝对中断，并保留共同覆盖和
新增覆盖诊断。不得用四段HOTA或P95的简单平均替代官方COMBINED或原逐序列计时。

以本轮未调参Tiny640为搜索对照：候选须HOTA、IDF1、MOTA和Recall不低于该对照，同时FP、
IDSW与原定义h<100中断不增加，并至少一项严格改善，才记为“无上述回退的改进候选”。采用
未舍入值，指标误差仅用于已证明的数值复核，不作为事后质量容差。若有候选，按HOTA降序、
IDF1降序、小目标中断升序、IDSW升序、FP升序和配置ID依次排序，最多保留3组。
没有满足这些条件的配置时明确报告“未找到无回退候选”，另列非支配取舍，不自动放宽标准。

该筛选标签不等于原连续性门槛通过。原Tiny416参照下的绝对中断减少要求单独计算，旧FAIL
不变；若只能以部分指标回退换其他收益，采用前必须明确新的权衡标准并重新确认。

## 固定开发视频事件对照

保留原Tiny416、未调参Tiny640及最多3组候选，共最多5种配置。使用相同的Walk1、Browse1、
EnterExitCrossingPaths1front，沿用已有ROI、line、dwell、事件真值与匹配协议，不修改规则
补足漏报。零正常丢帧、零序列缺口是计分有效性前提；无效轮次保留日志，不计入质量排名。

分别报告三类事件及聚合TP/FP/FN、Precision/Recall/F1，以及检测数、跟踪帧、轨迹观测、
TRT/E2E P95、事件I/O、FPS与遥测。候选选择先比较聚合事件F1，同时逐类检验相对Tiny416和
未调参Tiny640的退化。无独立改善或存在需要取舍的类别回退时不自动指定最终默认配置。
开发视频用于选择，不能冒充独立验证。参数一经选定，后续性能矩阵不再逐行调参。

## 最终配置性能矩阵

Tiny640单独新表，不能把README中的Nano历史矩阵换标题或复用旧数据。计划覆盖
720p/1080p × 25W原时钟/MAXN_SUPER锁频 × MP4V/x264，共8个工况；Tiny416以x264在相同
四种输入/功率条件下作对照。x264为主要输出路线，MP4V保留编码对照；720p MAXN_SUPER为
主要实时性目标，1080p和25W表现作为补充，不扩大硬实时目标。功率及锁频组合不同，差异
不能只归因功率模式。设备实际矩阵开始前再冻结执行配方并确认临时停服窗口。

所有行固定同一组五阈值、buffer、规则、输入队列2、输出队列4、300帧预热及3600测量帧。
列出engine输入尺寸、视频分辨率、功率/时钟、编码器、有效FPS、预热/正常丢帧、序列缺口、
target_reached、TRT/E2E/预处理/后处理/ByteTrack/事件I/O P95、视频提交/写入、事件输出、
CPU/GPU、内存、VDD_IN功率、温度及保护计数。未执行行写NOT_RUN，不插值、不借用其他尺寸。
CSI真实活动记录与开发集F1分开，不要求通过反复移动相机把受限场景旧轮次改判通过。

原30FPS、E2E P95≤33.33ms、零正常丢帧/缺口和完整写出要求保持，定义沿用v2，不变更计时
边界。OC计数在停服、功率切换、锁频、加载、预热、测量和恢复阶段分别采样，先定位旧OC3+1
风险；不把它新增为旧协议的自动FAIL条件，也不关闭保护。最终配置仍需至少60分钟持续运行，
保留全程分窗指标，不能用最后一段延迟环形窗口冒充整小时P95。

## 部署与发布边界

模型、ONNX、plan、原始GT/视频/截图/片段和运行目录不提交。设备阶段复用已核验engine，
不升级系统或平台依赖；停止服务前保存状态，结束或异常恢复原功率/时钟及Tiny416服务，
验证实际engine、active/running、NRestarts与新真实帧。sudo仍在设备远程终端验证。

矩阵与调参报告只填写实测值。候选推荐、默认部署迁移、提交及推送分别审核，不因单项30FPS
或开发集最高分自动修改systemd、默认engine或README默认命令。

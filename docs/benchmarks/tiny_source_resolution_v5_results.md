# Tiny 同源分辨率开发对照 v5 结果

结论：本轮未支持“原生720p使Tiny640的事件质量优势更明显”。原生输入下，两者聚合F1均为
66.67%；同源低清下，Tiny416为66.67%、Tiny640为70.59%。Tiny640在两种源分辨率下都补到
同一次较近骑行者停留，但远景片仍漏掉全部3个参考事件，原生输入下还多出一次入区误报。
更多检测与轨迹观测没有稳定转化为完整事件收益。

状态为`DEVELOPMENT_NOT_GATED`，不是新独立留出或默认切换验收。旧MOT17无回退门槛FAIL、
CAVIAR全部结果及CSI限制保留；默认仍为Tiny416，不追加调参、CSI矩阵或持续运行测试。

序列缺口0、计分预热丢弃0。未自动重试或延长窗口。恢复服务并完成核验后才执行CPU计分。

## 逐帧差异诊断

以下帧号均从0开始；ID仅在各自视频/模型任务中有效。参考框重叠和原图抽查只用于解释，
不构成新的稠密GT配对；不修改主计分及标签。

### 远景 B：增加观测，但三个参考事件仍全部漏报

- 两组416在全片均无已确认轨迹。原生640形成304个轨迹观测，低清640为114，但均为0 TP。
- 原生640的目标ID1仅在480–489、508–547、554–573帧有观测。第一次入区报警在481帧，
  比参考410帧晚71帧，超过固定60帧容差；按协议同时保留入区FN和该报警FP。
  636帧又由ID2报警；低清640在652帧由ID1报警，均为过晚FP，不能叫正确即时入区。
- 原生640在489→508和547→554之间分别缺18、6帧，超过停留规则允许的3帧缺口；持续在区
  计时被重置，未达到3秒。低清640更晚建立轨迹，且在区观测也碎片化。
- 原生640的ID1在573帧最后锚点约`(514.19,365.40)`，线位于x=520；此时仍在epsilon带内。
  `epsilon=0.01`在x方向等价12.8原图像素，需要稳定到x<507.2才确认另一侧。参考穿线582帧
  无轨迹；ID2从635帧才在另一侧建立，不能把跨ID观测拼接成穿线。低清640在该穿线窗口
  同样无轨迹。更多原生细节确实增加观测，但没有完成所需的身份和时序条件。

### 较近 C：停留改善与误报并存

- 两组640都在446帧正确触发骑行者停留。原生416的对应ID2在368–380、468–478帧分别
  缺13、11帧；低清416的ID2在372–381、469–476帧分别缺10、8帧，持续计时反复重置，
  两组均漏报该停留。640的改善在两种源输入下相同，不能单独归功于原生720p。
- 原生416的行人ID1在200帧入区正确，209帧再次入区为FP。锚点x在202帧为780.07，
  203–207帧约779.81–779.89，208帧回到780.82；ROI左边界为780。此处是同一ID的
  预测框底边抖动导致退出后重入，不是新增真实人物，也不是一次ID切换。
- 原生640的行人ID1首次停留284帧正确，590帧再次停留为FP。ID未变，但428–435及
  484–499的观测缺口超过3帧；500帧恢复后的计时在590帧再次达到3秒。
  低清640同一ID在480–494缺15帧，495恢复、585再次停留为FP。两组都存在已报警人物
  在中断后重新计时的问题，不能只报补到的骑行者停留。
- 低清416在567帧有停留FP。455帧附近ID1对应行人、ID2对应骑行者；520/550帧原图及
  参考框重叠检查中，行人已对应ID2，ID1向左随骑行者移动，支持两者在交会附近身份互换
  的诊断。现有事件匹配按类型、时间、方向和锚点，不要求GT人物ID，因此539帧行人穿线
  仍计TP。不得据事件TP推断身份连续性正确，也不把本次抽查写成官方IDSW总数。

所有7个FP均纳入解释：B原生640入区2次、B低清640入区1次；C原生416入区1次、C原生640
停留1次、C低清416停留1次、C低清640停留1次。不能跨组把同一视频的重复实验当独立事件样本。

tegrastats每500ms采样，统计范围为单任务全窗口，含输入哈希校验、engine初始化和回放，

1804–1951MB，CPU均值13.68–15.75%，GPU均值11.30–33.01%，最高GPU负载99%。
Tj最高57.093°C，GPU最高56.281°C；每项OC1/2/3计数差均为0。cv0/cv1/cv2温度读数为
EAGAIN，保留N/A。CPU/GPU/EMC控制前后相同，但DVFS动态频率和零OC不足以证明全程无热降频，
该结论仍为N/A；本轮未关闭温控。

E2E P95、截图/事件片段I/O、采集队列和编码队列丢帧均为N/A：本顺序质量入口只写逐帧trace，
截图、片段及标注视频均为`NOT_PRODUCED_trace_only`。没有媒体文件不额外增加事件FN，

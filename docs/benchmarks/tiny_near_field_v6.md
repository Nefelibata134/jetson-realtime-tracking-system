# Tiny416 / Tiny640 近景事件开发协议 v6

状态：六项 Jetson 回放、计分和原始证据核验已完成，结果为 `DEVELOPMENT_NOT_GATED`，
详见[近景开发结果 v6](tiny_near_field_v6_results.md)。预测前冻结清单的 `NOT_RUN` 快照保留不改。
本协议用于检查门口低密度近景是否值得继续验证，不预设 Tiny640 优于 Tiny416，
不替代 CAVIAR、MOT17 或同源分辨率 v5 的结果，不用于默认模型晋级。

## 派生像素与时间轴

- 源文件为官方 r13 H.264 转码分发，1920×1072、声明 30 FPS；不是原生720p录像。
- 顺序解码源文件全部 9,000 帧，再选固定窗口；不快进取关键帧，不去重或插帧。
- 上下各补 4 像素 BGR `(114,114,114)`，得到 1920×1080，随后以
  `OpenCV INTER_AREA` 在横纵方向均缩放 `2/3`，输出 1280×720 PNG。
  不裁切、不拉伸、不追加有损编码。源几何点映射为 `(2x/3, 2(y+4)/3)`。
- 每帧记录源解码序号、源 BGR 像素 SHA-256、派生像素 SHA-256、PNG 文件 SHA-256，
  写入后回读核对像素。两个模型读取同一份派生 PNG。
- 源 AVI 包没有 PTS。回放时间定义为 `floor(sequence * 1e9 / 30)` 纳秒，
  明确标记为派生解码序号时间轴，不能声称保留了原始采集 PTS。
  原始摄像头丢帧/重复采集情况未知，不填成零；派生与回放阶段的完整性另行检查。
- 不丢弃计分预热帧：`warmup_frames=0`。阶段 P95 包含首帧冷启动影响。

## 固定比较与预测前审核

仅 `derived720_tiny416` 和 `derived720_tiny640` 两组，共六次回放。
复用配方中已记录哈希的两份 engine，不重建、不训练；输入尺寸由 engine 契约核对。
五个阈值显式固定为 score/NMS/track/new-track/match =
`0.10 / 0.45 / 0.30 / 0.40 / 0.80`。
ByteTrack `frame_rate=30`、buffer 30、second-match 0.5、unconfirmed-match 0.7，
实现与旧轮次相同，不引入之前的两组调参候选。

三段共用归一化 ROI、有限警戒线和同一 ROI 内 3 秒停留规则；ROI 确认 2 帧、
线确认 1 帧、稳定侧容差 0.01、停留确认 2 帧、最大间断 3 帧。
在读取预测前完成以下审核，并将最终几何、完整窗口事件参考和原图观测通过 SHA-256 绑定：

1. 标注每次事件的人物、帧序号、方向、底边中心锚点及事件附近至少两个原图观测。
   停留记录进入帧与达到 3 秒的帧，不把动作名称或“站着不动”代替在区计时。
2. 明确门扇遮挡、下肢出画与不可判定边界；不补猜遮挡后的脚部位置。
   框宽随手臂动作改变也会影响底边中心，须与人物实际跨越区分，保留边界不确定区间。
3. 原图抽帧覆盖整段只能用于定位；关键事件需加密复核。尚未完成的标注不得设置
   `complete_annotation=true`，不能将未完成参考当作零事件负例。
4. 标注等待、快速通过与前后背景中的不应报警区间，不能只保留正例或成功动作。
   不确定性未解决前不运行模型；禁止看过预测后修改规则或参考来提高分数。

匹配复用 `evaluate_caviar_events.match_events`：按视频、类型和规则划分，
一对一、方向一致、60 帧 / 2 秒容差、归一化锚点距离 0.2。
主结果先冻结事件时刻；最早/最晚视觉边界只作敏感性分析，不替换主分数。
逐视频、逐事件类型与聚合均报告 TP/FP/FN 和 Precision/Recall/F1，聚合先加计数，
零分母为 N/A。开发结果为 `DEVELOPMENT_NOT_GATED`，不自动选默认模型。

## 工具与完整性

主机准备与校验入口：

```bash
python3 -B scripts/prepare_near_field.py prepare --input SOURCE_AVI --output NEW_PREPARED_DIR
python3 -B scripts/prepare_near_field.py verify --input NEW_PREPARED_DIR/CLIP_ID/frames.json
# 仅在三段完整标注与几何完成预测前审核后执行：
python3 -B scripts/prepare_near_field.py freeze --input SELECTION_JSON --output NEW_FREEZE_DIR
```

上述大写路径需替换为实际本地路径；所有准备、冻结和回放目录均拒绝复用。
原图、派生帧、标注、原始日志和运行输出只保存于本地排除目录，不进入 Git。

`source_resolution_replay.py` 按冻结协议选择输入适配器：v5 保持原四组和原生/低清契约，
v6 使用 `near_field_replay.py` 的派生输入契约；共用 C++ 回放、Detector、ByteTrack、
事件实现、完整帧门禁及计分。主机 `--validate-job` / `--self-test` 只验证接口，
不代表 TensorRT 链接、Jetson 推理或质量测试。

回放必须每个冻结帧正好一次，帧序号及派生 PTS 一致，零意外丢帧、零序列缺口，
`target_reached=true` 才可计分；失败留证，未执行任务保持 `NOT_RUN`。
输出检测数、跟踪帧、轨迹观测、关键事件窗口的 ID/锚点候选及逐阶段 P95。
窗口空间候选不等于已确认的 GT 人物身份，不直接据此计算身份切换真值。

顺序 PNG 回放 FPS 从首帧读取开始，至最后 trace flush 结束，包含读取与日志开销，
不等于 CSI 实时链路吞吐。此入口不采集完整 E2E 或事件媒体 I/O，保持 N/A；
`NOT_PRODUCED_trace_only` 不能冒充截图、片段、标注视频留存验证，也不计作事件 FN。

不修改功率配置、系统依赖、systemd 或默认模型。

冻结时再次核对全部 2,550 帧的 PNG 文件、像素和时间轴；通过只说明输入完整性，
不说明模型准确率。六项主机任务结构检查不加载 engine，不替代设备端资产核验与推理。
板端质量回放前仍需完成设备端独立源码/输入同步、编译、engine 哈希核验及新窗口确认。
若近景结果有继续价值，再单独验证实际 CSI720p、目标约30 FPS和活跃事件负载；
不得用本轮 PNG 回放替代该结论，也不自动扩大性能矩阵或进行长期持续运行。

# Jetson 实时跟踪与安全事件分析系统 v1.0.0

该版本建立了连续 Jetson 视频分析的第一个稳定系统边界：采集、TensorRT 检测、多目标
跟踪、安全事件、证据持久化、遥测、服务监管与故障恢复。

## 主要能力

- 文件、IMX219 CSI 和 H.264 RTSP 输入统一实现 `IFrameSource` 契约。
- 有界丢弃最旧帧队列在过载时优先保留当前画面。
- YOLOX TensorRT 检测为按类别关联的 ByteTrack 提供输入。
- ROI 入侵、定向穿线和停留规则生成版本化 JSONL 记录，可选截图及事件前后片段。
- 指标把同步截图/JSONL 延迟与异步事件片段/标注视频编码工作分开。
- systemd 监管使用 readiness 与真实帧 watchdog 通知，并支持 SIGTERM 有序收尾和有界
  本地保留。

## 实测结果

- 完整 720p/25W 流水线：30.03 FPS、采集丢帧率 0.00%、TensorRT P95 3.53 ms、
  端到端 P95 9.99 ms、平均输入功率 8.69 W。
- 完整 720p/MAXN_SUPER 流水线：30.04 FPS，端到端 P95 8.46 ms。
- 固定 MOT17 留出划分：HOTA 38.89、IDF1 46.75、MOTA 39.19。
- 60 分钟 CSI 持续运行：活跃覆盖率 100%，进程零重启，watchdog 和真实帧零停滞，
  30.00 FPS，采集丢帧率 0.00%。
- 受控进程崩溃与 RTSP 中断测试都恢复到真实帧处理。

协议与证据边界见[完整流水线基准](../benchmarks/full_pipeline_benchmark.md)、
[MOT17 评估协议](../benchmarks/mot17_evaluation_protocol.md)和
[服务稳定性报告](../operations/stability_report.md)。

## 兼容性

已在 Jetson Orin Nano 8GB、JetPack 6.2.1、Ubuntu 22.04、CUDA 12.6、
TensorRT 10.3、GStreamer 1.20 与 IMX219 CSI 摄像头上验证。TensorRT plan 必须在
目标 Jetson 上重新构建。

## 升级说明

这是第一个版本化发布。平台或 TensorRT 发生变化后，现有源码副本应重新生成 CMake
构建目录和目标设备专用 TensorRT plan。

## 已知限制

- COCO 预训练检测器不是针对具体部署场景训练的模型。
- 实测 1080p OpenCV MP4V 软件编码慢于 30 FPS；输出丢帧与实时分析主链路隔离。
- 为保持证据顺序，截图和 JSONL 发布是同步操作，慢存储会提高事件帧延迟。
- RTSP URI 作为运行参数传入，本地进程查看工具可能看到 URI 内嵌的凭据。
- 证据保存在本地；本版本不包含远程传输和设备集群控制。
- 已发布耐久结果只覆盖单台设备 1 小时，不是多设备或多日测试。

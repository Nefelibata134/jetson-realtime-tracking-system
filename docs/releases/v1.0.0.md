# Jetson Realtime Tracking System v1.0.0

This release establishes the first stable system boundary for continuous
Jetson video analytics: capture, TensorRT detection, multi-object tracking,
safety events, evidence persistence, telemetry, supervision, and fault
recovery.

## Highlights

- File, IMX219 CSI, and H.264 RTSP sources share one `IFrameSource` contract.
- A bounded drop-oldest queue prioritizes current frames during overload.
- YOLOX TensorRT detection feeds class-aware ByteTrack identities.
- ROI intrusion, directional crossing, and dwell rules emit versioned JSONL
  records with optional snapshots and pre/post-event clips.
- Metrics separate synchronous snapshot and JSONL latency from asynchronous
  event-clip and annotated-video encoding work.
- systemd supervision uses readiness and real-frame watchdog notifications,
  with graceful SIGTERM finalization and bounded local retention.

## Measured Results

- Complete 720p/25W pipeline: 30.03 FPS, 0.00% capture drop, 3.53 ms TensorRT
  P95, 9.99 ms end-to-end P95, and 8.69 W mean input power.
- Complete 720p/MAXN_SUPER pipeline: 30.04 FPS and 8.46 ms end-to-end P95.
- Fixed MOT17 holdout: 38.89 HOTA, 46.75 IDF1, and 39.19 MOTA.
- 60-minute CSI soak: 100% active coverage, no process restart, no watchdog or
  real-frame stall, 30.00 FPS, and 0.00% capture drop.
- Controlled process crash and RTSP outage tests both returned to real frame
  processing.

Protocols and evidence boundaries are documented in the
[full pipeline benchmark](../benchmarks/full_pipeline_benchmark.md),
[MOT17 evaluation protocol](../benchmarks/mot17_evaluation_protocol.md), and
[service stability report](../operations/stability_report.md).

## Compatibility

Validated on Jetson Orin Nano 8GB with JetPack 6.2.1, Ubuntu 22.04, CUDA 12.6,
TensorRT 10.3, GStreamer 1.20, and an IMX219 CSI camera. TensorRT plan files
must be rebuilt on the target Jetson.

## Upgrade Notes

This is the first versioned release. Existing source checkouts should rebuild
the CMake tree and regenerate target-specific TensorRT plans after platform or
TensorRT changes.

## Known Limitations

- COCO-pretrained detectors are not scene-specific models.
- Measured 1080p OpenCV MP4V software encoding is slower than 30 FPS; output
  drops are isolated from the real-time analytics path.
- Snapshot and JSONL publication are synchronous to preserve evidence order,
  so slow storage can raise latency on event frames.
- Credentials embedded in an RTSP URI can be visible through local process
  inspection because the URI is passed as a runtime argument.
- Evidence remains on local storage; remote transport and fleet control are
  not included.
- The published endurance result covers one device for one hour, not a
  multi-device or multi-day campaign.
